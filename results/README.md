# `results/` — every committed number

A result nobody else can inspect is not a result, so the small, text-free outputs are committed.
Large or text-bearing files stay local (see [.gitignore](../.gitignore)). Every number in `docs/`
traces back to a file here, and most files are regenerated by one CLI call.

## Layout

| Path | What it is | Written by |
|---|---|---|
| [`registry.csv`](registry.csv) | One row per run (173): run id, task, model, preprocessing, recipe, seed, split, metrics, config hash | every `baseline run` / `train run` / study that trains |
| [`runs/<run-id>/`](runs/) | Per run: `metrics.json`, `config.yaml`, `env.json` (git SHA, packages, CPU/GPU, seed). Validation predictions (`*-val/preds.csv`) carry no text and are kept for paired comparisons | the same commands |
| [`test_evaluations.log`](test_evaluations.log) | Every evaluation on UIT-VSFC test, appended with date, run id and reason (28 so far: Gate G4 and Cycle 1's closing gate) | any test evaluation |
| [`provenance.json`](provenance.json) | Each run's recorded source hash resolved to the commit whose code it executed | `vifeedback results provenance` |
| [`data_report.json`](data_report.json) | Phase 0 integrity and profiling of UIT-VSFC: splits, labels, overlap, lengths | `vifeedback data report` |
| [`phase2_summary.json`](phase2_summary.json), [`phase3_summary.json`](phase3_summary.json) | Gate G2 (PhoBERT reproduction) and G3 (word-segmentation ablation) aggregates, 5 seeds | the gate runs (2026-09-22); read by `notebooks/02_results.ipynb` |
| [`g4_baseline_test.json`](g4_baseline_test.json), [`g4_phobert_test.json`](g4_phobert_test.json) | Gate G4: the locked test evaluation of the baseline and the best PhoBERT configuration | the gate run; read by `notebooks/02_results.ipynb` |
| [`segmentation_latency.json`](segmentation_latency.json) | Gate G3: CPU cost of each word segmenter | the G3 benchmark |
| [`studies/`](studies/README.md) | Research Cycles 0–5: one folder per study, each with the command that regenerates it | `vifeedback study …` |
| `figures/` | EDA and result figures, regenerated, not committed | `vifeedback data report`, the notebooks |

## Rules

- **Append-only.** A run directory cannot be overwritten by a different configuration (the run id
  includes a config hash). `vifeedback results merge` brings in another machine's results (Kaggle)
  without overwriting anything.
- **No corpus text.** Test predictions, audit sheets and anything else holding UIT-VSFC, NEU-ESC or
  ViLexNorm sentences live in `*/local/` or in ignored files. Committed prediction files are keyed
  by row index ([DATA_CARD § 11](../docs/DATA_CARD.md)).
- **Negative results stay.** Deleting a failed run from the registry would falsify the record
  ([EXPERIMENT_MATRIX § 6](../docs/EXPERIMENT_MATRIX.md)).
- **Model weights are not here.** They are in the ignored `models/` folder; the published model is on
  the Hugging Face Hub, and `vifeedback serve reproduce` checks it against this record.
